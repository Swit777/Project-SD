# Схема Данных Player Experience

Одна строка — один ответ игрока о текущем субъективном удовольствии и признаки,
доступные до этого ответа. CSV: UTF-8, разделитель запятая, десятичная точка.

## Служебные Поля

| Поле | Смысл |
|---|---|
| `response_id` | Уникальный непустой идентификатор ответа |
| `player_id` | Псевдоним игрока; нужен для независимого разделения |
| `timestamp` | Дата и время ответа с часовым поясом; в исходном анализе UTC |
| `enjoyment` | Цель 0–100; исходная шкала PowerWash 0–1000 делится на 10 |

Эти четыре поля не подаются модели как входные признаки. Для нового обучения обязательны;
для прогноза могут отсутствовать. Минимум 12 разных игроков для эксперимента.

## Общие Признаки

| Поле | Смысл / единицы |
|---|---|
| `job` | Название уровня |
| `mode` | Режим игры |
| `washer`, `nozzle` | Последнее наблюдавшееся до ответа оборудование в эпизоде, иначе unknown |
| `session_minutes` | Длительность сессии из телеметрии, минуты |
| `episode_minutes` | Время после последнего старта/возобновления уровня, минуты |
| `campaign_progress`, `level_progress` | Прогресс кампании и уровня, доля 0–1 |
| `subtasks_total` | Число завершённых подзадач в текущем эпизоде до ответа |
| `overall_rate` | Подзадачи в минуту с начала текущего эпизода |
| `overall_gap_mean` | Средняя пауза между завершениями в эпизоде, секунды |

Текущий эпизод начинается на `job_started` или `job_resumed`, прерывается на выходе
из уровня/игры либо новом логине. Не подтверждённый эпизод или несовпадение job/mode исключает ответ.
Одновременные граничные события трактуются консервативно: закрытие/логин имеют приоритет перед стартом.
Временное окно не пересекает начало эпизода. Длительность включает возможное бездействие;
она не является измерением непрерывно активного времени.

## Временные Признаки

Для каждого окна `W` из конфигурации, по умолчанию 1, 5, 15 минут:

| Поле | Смысл / единицы |
|---|---|
| `wW_count` | Число завершений внутри окна и текущего эпизода |
| `wW_rate` | Число завершений / реально доступную длительность окна в минутах |
| `wW_gap_mean` | Средняя пауза между завершениями внутри окна, секунды |
| `wW_gap_cv` | Population SD пауз / среднюю паузу; нужны минимум две положительные в среднем паузы |
| `wW_progress_gain` | Неотрицательная разница прогресса последнего и первого наблюдаемых завершений в окне |
| `wW_coverage` | Доля времени окна после старта эпизода, от 0 до 1 |

`W` заменяется числом: например, `w5_rate`. Поле `progress_gain` не измеряет весь реальный
прирост прогресса за окно: при менее чем двух конечных измерениях оно равно 0.
`coverage` отражает обрезание окна границей эпизода, а не полноту регистрации событий.

- `seconds_since_subtask`: время после последнего завершения в эпизоде, секунды, максимум 3600; без завершений пропуск.
- `recent_rate_change`: rate самого короткого окна минус rate самого длинного.
- Строго исключаются события с временем `>= timestamp` ответа; точность источника — секунды.

## Проверки И Пропуски

Проверяются необходимые колонки, непустая таблица, числовой формат и отсутствие бесконечностей,
валидность целевой шкалы, дат, идентификаторов, уникальность `response_id` и число игроков.
Числовые пропуски допустимы в признаках; медианная импутация обучается только на train,
добавляются индикаторы пропусков. Неизвестные категории кодируются без падения.
Значения с бессмысленными единицами, утечки при подготовке чужого CSV, лицензию и правдивость источника
валидатор автоматически определить не может: схема не заменяет контроль качества и семантики.

Пример для прогнозов: `reports/player_experience/example_prediction_input.csv`.
Он содержит 50 настоящих строк признаков из test-игроков без цели и ID; это пример формата,
не отдельный внешний валидационный набор. ID этих строк сохранены отдельно.
