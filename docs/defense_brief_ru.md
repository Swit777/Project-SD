# Кратко для защиты темы

## Тема

**Прогнозирование сложности процедурно сгенерированных игровых уровней с помощью Game AI и вероятностного моделирования.**

## Проблема

При процедурной генерации можно получить тысячи вариантов уровней. Ручная оценка сложности через playtesting занимает много времени и плохо масштабируется. Поэтому нужна автоматическая система, которая заранее оценивает, насколько уровень будет сложным для прохождения.

## Гипотеза

Структурные признаки уровня позволяют предсказывать вероятность успешного прохождения AI-агентом.

Примеры признаков:

- длина кратчайшего пути;
- плотность препятствий;
- число тупиков;
- доступная площадь;
- ветвистость маршрутов;
- степень прямоты маршрута.

## Метрика сложности

Сложность определяется как вероятность непрохождения уровня:

```text
difficulty = 1 - P(success)
```

Это делает сложность не субъективной оценкой, а измеряемой вероятностной величиной.

## Источник данных

Данные генерируются в собственной grid-world среде по фиксированным `seed`. Это значит, что датасет можно полностью воспроизвести или расширить, изменив конфигурацию.

Источник данных конкретный:

```text
configs/default.json -> генератор уровней -> data/processed/levels_results.csv
```

## Почему это легально

Данные не скачиваются из закрытых источников и не содержат персональных данных. Они создаются программно внутри проекта. Поэтому нет проблем с авторскими правами, пользовательскими соглашениями или приватностью.

## Оригинальность

Оригинальность проекта состоит в разработке собственного исследовательского pipeline:

- собственная генерация уровней;
- собственная метрика сложности;
- извлечение структурных признаков уровня;
- запуск разных AI-агентов;
- реализация A* и tabular Q-learning;
- сравнение ML-моделей;
- EM-кластеризация уровней;
- байесовская оценка неопределенности;
- group cross-validation по `level_id`;
- calibration curve для вероятностного прогноза;
- объяснение результата через важность признаков.

## Инструменты

- `Python` - основной язык;
- `pandas`, `numpy` - обработка данных;
- `scikit-learn` - Logistic Regression, SVM, Random Forest, Gaussian Mixture Model;
- собственный код - генерация уровней, A*, Q-learning, признаки;
- `matplotlib` - графики;
- `Streamlit` - приложение для загрузки другого датасета;
- `unittest` - автоматические тесты.

## Почему это не просто Python-библиотека

Библиотеки используются только для отдельных этапов обучения и визуализации. Главная часть проекта - это постановка задачи и pipeline:

```text
seed -> level -> features -> agent runs -> dataset -> models -> uncertainty -> explanation
```

Если использовать другой seed или загрузить CSV той же структуры, система заново проведет валидацию, обучение, оценку метрик и построение отчетов.

## Текущий результат MVP

- датасет: 6480 строк;
- уровней: 1620;
- агенты: random, greedy, A*, Q-learning;
- лучшая модель классификации: Random Forest;
- ROC-AUC: около 0.991;
- GroupKFold ROC-AUC: около 0.992;
- модель сложности уровня: R2 около 0.910.

## Что можно сказать на вопрос об применимости

Метод можно использовать в game development как инструмент предварительной балансировки уровней. Перед тем как отдавать уровни игрокам или тестировщикам, система может автоматически выделить слишком легкие, слишком сложные или плохо сбалансированные уровни.
