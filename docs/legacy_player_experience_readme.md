# Player Experience Lab (Archived)

**Оценка субъективного игрового опыта по динамике поведения игрока.**

Исследовательский проект на открытой телеметрии PowerWash Simulator. Не нужно создавать игру,
набирать участников или генерировать искусственные игровые логи. Проект продолжает тему диплома
об анализе поведения игрока, но проверяет предпосылку адаптации: можно ли по действиям оценить
самооценку удовольствия, а не просто накопить события.

## Исследовательский вопрос

Помогает ли история выполнения игровых подзадач за последние 1, 5 и 15 минут оценивать **Enjoyment**
точнее, чем контекст уровня и общая активность в текущем игровом эпизоде?

Гипотеза: одинаковый Random Forest с временными признаками имеет меньшую ошибку на **новых игроках**,
чем Random Forest только с агрегированными признаками. Цель имеет шкалу 0–100.
Проверяется предсказательная связь, а не причинный эффект адаптации игры.

## Текущий Результат

Подготовлены **8 590 ответов от 1 077 игроков**. Train / validation / test разделены по игрокам.
Основное сравнение: Δ MAE = **−0.137**, 95% bootstrap-интервал **[−0.295; +0.030]**.
Положительное Δ означало бы преимущество динамики. Убедительных свидетельств такого преимущества
в текущем протоколе нет. Выбранная по validation модель — постоянная медиана; test MAE по игрокам **12.561**.
Результат нельзя выдавать за успешное распознавание эмоций или подтверждение эффективности адаптации.

Числа относятся к текущей конфигурации и подвыборке. Отчёт при новом обучении пересчитывается автоматически:
[исследовательский отчёт](reports/player_experience/research_report_ru.md).

## Запуск

Проверенная среда: **Python 3.14.2**, Windows. Зависимости зафиксированы в `requirements.txt`.

```powershell
python -m pip install -r requirements.txt
python run_pipeline.py run-all
python -m streamlit run player_experience_app.py
```

Первый запуск скачивает архив OSF около 838 MB и кодбук. Полная распаковка архива не требуется.
Уже подготовленные данные находятся в `data/processed/player_experience.csv`, результаты —
в `reports/player_experience/`. Повторная подготовка использует проверенный Parquet-кеш.

Отдельные стадии:

```powershell
python run_pipeline.py download
python run_pipeline.py prepare
python run_pipeline.py train
python -m unittest discover -s tests -v
```

Настройки выборки, seed, окон, моделей и bootstrap: `configs/player_experience.json`.
Другую конфигурацию передают **до команды**:

```powershell
python run_pipeline.py --config configs/player_experience.json run-all
```

## Другой Датасет

Приложение поддерживает прогноз и повторный эксперимент для **подготовленного CSV с той же схемой
и смыслом признаков**. Произвольный CSV, данные другой игры без преобразования или исходный архив
с другим форматом автоматически совместимыми не становятся.

- Для прогноза достаточно входных признаков, цель и ID не обязательны.
- Для обучения нужны также `response_id`, `player_id`, `timestamp`, `enjoyment` и минимум 12 игроков.
- Неизвестные значения уровня/оборудования обрабатываются, но качество на новой области не гарантируется.
- Отдельные эксперименты приложения сохраняются в `reports/player_experience/uploads/`, основной результат не затирается.

```powershell
python run_pipeline.py predict --input reports/player_experience/example_prediction_input.csv --output reports/player_experience/example_predictions.csv
python run_pipeline.py train --input path/to/new_prepared.csv --output reports/new_experiment
```

Смена набора должна воспроизводить **методику**, а не те же численные результаты.
Формат описан в [схеме данных](docs/player_experience_schema_ru.md).

## Что Реализовано

1. Скачивание конкретной версии открытых данных с проверкой размера и SHA-256.
2. Выборка игроков и ответов по seed, реконструкция игровых эпизодов, исключение невалидного контекста.
3. Собственное извлечение временных признаков только из прошлых событий, без переноса истории между эпизодами.
4. Сравнение среднего и медианы, Ridge, двух Random Forest и Bayesian Ridge.
5. Разделение по игрокам, равные суммарные веса игроков при обучении, выбор модели по validation и GroupKFold на development.
6. Парный bootstrap по игрокам, сравнение окон, permutation importance, дескриптивные интервалы ошибок.
7. Тёмное приложение для результатов, аудита, фильтрации и загрузки другого CSV; автоматически сформированный отчёт и графики.

Это не новая реализация Random Forest с нуля. Собственный вклад — исследовательский вопрос,
подготовка телеметрии и экспериментальный протокол. SHAP/LIME пока не реализованы;
объяснение признаков выполнено через permutation importance.

## Данные И Ограничения

Источник: [PowerWash Simulator Research Dataset](https://doi.org/10.17605/OSF.IO/WPEH6), **CC0-1.0**.
[Статья авторов](https://www.nature.com/articles/s41597-023-02530-3) и
[их код обработки](https://github.com/digital-wellbeing/pws-data).
В закреплённом архиве обработаны 702 209 строк ответов на разные вопросы и 14 376 699 событий выполнения подзадач.
Это не количество независимых участников и не размер итоговой обучающей таблицы.

До фильтрации эпизодов выбраны 18 704 ответа Enjoyment от 1 200 игроков. Исключены 10 106 ответов без
подтверждённого активного эпизода и 8 с несовпадающим контекстом. Это существенная фильтрация,
которая может смещать выборку. Аудит находится в `data/processed/player_experience_audit.json`.
Нельзя автоматически распространять вывод на все игры, считать Enjoyment меткой усталости или доказать
пользу адаптации без отдельного эксперимента. Интервалы прогнозов не имеют гарантии покрытия.

## Структура

```text
src/player_experience/       загрузка, признаки, модели, оценка, отчёт, CLI
configs/player_experience.json
data/raw/powerwash/          исходный архив и кодбук, не для GitHub
data/interim/powerwash/      проверенный кеш, не для GitHub
data/processed/              таблица признаков и аудит
reports/player_experience/   метрики, графики, модели, отчёт, манифест
docs/player_experience_*     схема данных и протокол
app.py                      текущее приложение
tests/test_player_experience.py
```

Манифест сохраняет seed, конфигурацию, версии зависимостей, SHA-256 входного CSV и исследовательского кода.
Точное численное повторение предполагает ту же версию данных и вычислительную среду.
Исходные данные, кеш, бинарная модель и загруженные пользователем CSV исключены из Git; модель строится командой `run-all`.
Публикация в GitHub не выполнена автоматически. Финальные слайды и оформленная статья для сдачи ещё требуют подготовки.
