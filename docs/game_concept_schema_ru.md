# Схема данных Game Concept Lab

## Прогноз

CSV в UTF-8, разделитель — запятая. Одна строка — одна концепция.
Шаблон доступен в приложении. Все входные столбцы обязательны, лишние столбцы не используются моделью.

| Поле | Значение |
|---|---|
| `log_price` | Натуральный `log(1 + недисконтная цена в USD)`, положительное конечное число |
| `log_age` | Натуральный `log(1 + возраст аналогов в годах)`, положительное конечное число |
| `language_count` | Целое число поддерживаемых языков, минимум 1 |
| `windows`, `mac`, `linux` | 0 или 1 |
| `genre_*` | 10 бинарных жанровых признаков; минимум один 1 |
| `mechanic_*` | 36 бинарных признаков найденных/заявленных элементов |
| `mechanic_count` | Сумма 36 флагов механик |

Жанровые столбцы: `genre_action`, `genre_adventure`, `genre_casual`, `genre_indie`, `genre_rpg`,
`genre_simulation`, `genre_sports`, `genre_strategy`, `genre_racing`, `genre_massively_multiplayer`.

Ключи элементов с префиксом `mechanic_`:

```text
crafting, base_building, survival, procedural_generation, permadeath, deck_building,
turn_based_combat, real_time_combat, skill_tree, loot, character_customization,
branching_story, puzzles, platforming, stealth, resource_management, farming,
fishing, taming, trading, automation, physics, parkour, rhythm, time_manipulation,
co_op, pvp, open_world, user_content, tower_defense, exploration, dating, quests,
boss_battles, destruction, vehicle_driving
```

Отсутствие признака в исследовательском корпусе означает «свидетельство не найдено», а не доказанное отсутствие.
Концепция заявляется самим пользователем; несовпадение этой семантики — дополнительный риск переноса модели.

## Обучение

Нужны все входы, а также:

| Поле | Значение |
|---|---|
| `appid` | Непустой уникальный идентификатор игры |
| `name` | Название |
| `developer_group` | Нормализованные названия разработчиков через `\|` |
| `release_date` | Дата релиза, рекомендуется `YYYY-MM-DD` |
| `owners_lower`, `owners_upper` | Конечные неотрицательные границы оценки, lower < upper |
| `owners_band` | 0: [0,20k]; 1: [20k,100k]; 2: [100k,500k]; 3: [500k,+∞) |
| `playtime_median_hours` | Медианные часы, конечное неотрицательное число или пустое значение |

Источник предоставляет интервалы, а не точное число владельцев. Интервал должен полностью помещаться
в один целевой диапазон. Пересекающий несколько диапазонов интервал автоматически не размечается.
Диапазоны интерпретируются как интервальные метки масштаба, не как точные продажи на их границах.
Смысл часов должен совпадать с медианой игрового времени SteamSpy; другие метрики нельзя подставлять под этим именем.

Минимум 100 игр и 20 независимых связных групп разработчиков. В train, validation и calibration
должны присутствовать все 4 целевых класса. После группировки размеры частей могут отличаться от заданных долей.
Нулевые часы не участвуют в обучении часов. Если положительных наблюдений мало, модель часов не строится.

Наборы с другой валютой, бесплатными играми, иной платформой или настоящими продажами требуют нового протокола,
а не просто переименования столбцов. Источник пользовательского CSV в отчёте маркируется как непроверенный.
Не загружайте pickle/joblib из сторонних источников: приложение принимает CSV, не исполняемые модели.

## Файлы корпуса

- `games.csv`: признаки, цели и метаданные подготовленной выборки.
- `mechanic_evidence.csv`: AppID, тип свидетельства, механика, фраза, отрицание, URL, происхождение.
- `feature_claims.csv`: текстовые кандидаты необычных возможностей; ещё не модельные признаки.
- `live_games.csv`, `live_mechanic_evidence.csv`: текущий прямой сбор, отдельно от обучающего снимка.
- `audit.json`, `scrape_manifest.json`: выборка, ограничения, проверки, SHA-256 и фактические результаты сбора.

Схема машинно читаемого ввода: `reports/game_concept/input_schema.json`.
Модельные входы не включают отзывы, оценки, аудиторию, игровые часы, ID или популярность тегов.
