# Ручная проверка игровых элементов

## Что измеряем

Подтверждает ли предоставленное описание, тег или категория Steam утверждение о механике?
Это проверка извлечения **заявлений из метаданных**, не экспертная оценка реального геймплея, качества или интересности.
Описание может не упоминать существующий элемент. Поэтому `0` означает «не подтверждено данными источника»,
а не «этого элемента точно нет в игре».

## Выборка

40 игр по отдельному SHA-256(seed:AppID)-отбору из исследовательского корпуса, без использования исходов продаж/владельцев.
Все 36 типов элементов для каждой выбранной игры: 1 440 задач, включая прогнозируемые отрицательные.
Форма содержит полный исходный контекст — описание, теги, категории и URL — но не метки аудитории.
Предсказания извлечения скрыты в интерактивной таблице и не экспортируются в экспертный CSV.

Манифест фиксирует SHA-256 корпуса, кеша описаний, неизменяемых задач и выбранных текстов, seed и версию словаря.
Задачи воспроизводятся; ранее сохранённые ответы не перезаписываются при создании той же выборки.
При изменении корпуса создаётся другая директория; старые ответы нельзя выдавать за аудит новой версии.

## Метки

| CSV `expert_label` | Значение в интерфейсе | Интерпретация |
|---|---|---|
| `1` | Подтверждено | Источник содержит достаточное свидетельство данного типа элемента |
| `0` | Не подтверждено | В представленном источнике такого свидетельства не обнаружено |
| `unclear` | Неясно | Противоречие, неоднозначная формулировка или недостаточная определённость |
| Пусто | Не рассмотрено | Работа ещё не выполнена; не отрицательная метка |

Для `1` желательно записать короткую подтверждающую фразу в `expert_notes`.
При противоречии тега и описания допустимо `unclear` с пояснением. Не домысливайте механики по личному знакомству с игрой.
Если нужна проверка настоящего геймплея, это отдельная разметка с другими источниками и определением цели.

CSV: обязательны `task_id`, `expert_label`; `expert_notes` необязателен. AppID и название элемента в экспорте справочные.
Вычисления используют исходные неизменяемые задачи, не подставленные в CSV прогнозы или механики.
Чужие ID, дубли, значения вне 0/1/unclear/пусто отклоняются. Импорт обновляет только перечисленные задачи.

## Результаты

TP: найденный и подтверждённый элемент; FP: найденный, но неподтверждённый; FN: пропущенный, но подтверждённый.
Precision = TP/(TP+FP), recall = TP/(TP+FN), F1 = 2TP/(2TP+FP+FN).
Метрики рассчитываются по рассмотренным бинарным меткам; `unclear` и пропуски исключаются и отдельно подсчитываются.
Пустой знаменатель означает неопределённую метрику, не нулевую точность.
Показываются число задач, покрытие игр, полностью размеченные игры и значения отдельно для каждой механики.

При частичной/избирательной разметке эти значения не характеризуют весь корпус. Даже полная форма относится
к конкретной случайной выборке и определению метки; межэкспертное согласие и проверка геймплея ещё не измерены.
Один разработчик-разметчик не является независимым подтверждением научной точности.
Для более сильного вывода нужны второй разметчик и заранее закреплённый контрольный набор после доработки правил.

## Команды и файлы

```powershell
python run_game_concept.py audit-create --games 40
python run_game_concept.py audit-evaluate --input path/to/mechanic_reviews.csv
```

Рабочая директория: `reports/game_concept/annotations/<идентификатор>/`.
`tasks.csv`, `games.json`, `manifest.json` неизменяемы; `reviews.csv` — сохранённые ответы;
`annotation_metrics.json` и `mechanic_metrics.csv` пересчитываются после сохранения.
Тексты и разметка остаются локально и исключены из Git.
Без экспертных ответов приложение не выдаёт выдуманную precision/recall. В текущей поставке ответы не заполнены.
